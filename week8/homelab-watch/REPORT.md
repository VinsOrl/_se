## Decisions (where the spec was open; simplest option taken)
- **Launcher**: `bin/hw`, because `hw/` (the package) and a launcher named `hw` cannot share a directory.
- **Extra file**: `hw/fix.py` for Phase 6 (spec's layout had 6 files, remediation had no home). Config loading and markdown rendering live in `collectors.py`.
- **Layout location**: project is `week8/homelab-watch/`. The original `homelab_watch.py` and `SPEC.md` in `week8/` are untouched and not committed.
- **Statuses**: failed ping/DNS/HTTP/TCP and a missing backup = `crit`; stale backup, failed unit, bad container, reboot required = `warn`. Comparisons are strict `>` like the original script, so exactly 85% disk is ok.
- **Container "warn"**: any container not `Up`, unhealthy or restarting. This includes old exited containers (e.g. a `hello-world` leftover on this machine); it is noisy by design, as in the original script.
- **Load** thresholds are per core (1-min load / cores, 1.5 warn, 3 crit), matching the original 1.5x rule.
- **History** stores a slim sample (overall status, metrics, per-check status), not the full report, so 30 days stays small.
- **Alert batching**: one message per run, one line per changed check. Per-check cooldown applies to *failure* alerts only; a recovery is always sent if its failure alert was sent. A check that disappears (a failed unit that recovered) counts as recovered.
- **If a webhook post fails** the state is still recorded (no retry spam); the error goes to stderr/journal.
- **`--fix` semantics**: `enabled=true` + `dry-run`/`auto` act during every `hw collect` (so the timer needs no flag). In `ask` mode `collect` does nothing unless you pass `--fix`. `--fix` with `enabled=false` does nothing and says so.
- **Successful auto-fix** sends one info line ("tried X, result ok") because the check never becomes bad in the stored state, so no normal alert would fire. Failures attach "tried X, result Y" to the normal alert.
- **Verification** re-collects everything (not one check) after `settle_seconds` (default 3) and looks at that check's key. Simple, costs a few seconds.
- **Disk cleanup** runs `sudo -n apt-get clean` / `sudo -n journalctl --vacuum-time=7d` (needs the sudoers snippet in README; without it the attempt fails and is logged), then `docker image prune -f`. It only triggers on a `crit` disk.
- **User vs system units**: failed units are detected in both scopes; user units restart with `systemctl --user`, system units with `sudo -n systemctl`. Service-check mappings (`fix_unit`) default to user scope (`fix_scope = "system"` to change).
- **Dashboard** Fix button: localhost-only client address + `X-HW-Token` (generated by `hw init`). It sends only an issue key; the server looks the command up itself.
- **Session cleanup**: while testing I removed `~/.local/share/homelab-watch` (it only held my test samples) and the temporary systemd units / test container.

## Known limits
- The dashboard's `/api/current` runs live collection per request (about 1-3 s, apt simulation is the slowest); fine for one viewer at 10 s refresh.
- Not tested against Discord/Telegram themselves (only a local generic webhook).
- `docker` collectors need the user in the `docker` group, otherwise Docker is skipped with a note.
- This machine's thermal zones sit near the 80/90 °C thresholds, so `hw collect --alert` will flap on them; tune `temp_warn`/`temp_crit` in config.

## What was built
- **Phase 0**: containers exiting with code 0 no longer warn (non-zero exit, restarting, unhealthy, created/paused do); `[checks] ignore_containers`. Flap protection: `[alerts] min_samples` (default 2) consecutive bad evaluations before an alert; a blip that clears never alerts or "recovers". DB migrates itself (adds `alert_state.bad`). - **Phase 7**: `hw/engine.py`: three collector tiers in threads (fast 2 s / medium 30 s / slow 10 min, `[engine]` config), one in-memory snapshot, alerts + remediation every `eval` (30 s), SQLite history every 60 s with retention pruning, SIGTERM shutdown. New collectors: CPU %, network rx/tx rate. `/api/current` is cache-only (about 20 ms). `GET /events` SSE (full snapshot, then changed results only). ## Decisions (simplest option taken)
- **Flap protection counts evaluations**, not 2 s ticks: in `hw serve` that is 30 s apart (so 2 samples is about a minute); in `hw collect` it is 5 min apart. History samples are separate (60 s).
- **Page actions need the token even for Mute/Check/Test alert**, using `[remediation] token`. With no token configured the buttons are hidden. Fix additionally needs `mode = "ask"`.
- **Dry-run** logs a given target once per hour instead of every evaluation.
- **Verifying a fix** refreshes the fast + medium tiers (not apt/backups) before reading the result.
- **History** now stores only status + metrics (the per-check map was unused) and `/api/history` thins to about 300 points, so 7d is cheap.
- **Lock** gates only `collect --alert/--fix`; plain `hw collect` still works while serving (writes an extra history row).
- **Uptime** is now a numeric `value` on the `uptime` result so the page can format it.
- Network rate skips `lo`, `veth*`, `docker*`, `br-*` to avoid double counting.
- Muted keys with `hours = 0` mean unmute.
